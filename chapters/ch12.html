CHAPTER 12 · 集成与实战 上

IDE 集成:把 Vim 装进 VSCode 与 IDEA

预计阅读 30 分钟(含练习约 1 小时)· 前置:第 1、11 章 · 本章演示 6 个

学习目标

  • 拿到两份可直接抄走的推荐配置:VSCodeVim 的 settings.json 片段与 IdeaVim 的 .ideavimrc 全文(逐项注明来源与默认值)
  • 打通五根导航桥:gd 跳定义、gh 悬停、K 文档、Ctrl+o/Ctrl+i 跳转链 —— vim 出发,IDE 导航
  • 用好 leader 键:自定义命令的统一发射台,把 <leader>d、<leader>w 练成肌肉记忆
  • 掌握 surround 三件套(ys 加壳 / cs 换壳 / ds 拆壳)与 gb 多光标
  • 学会冲突仲裁:一个键两个主人时,IDEA 用 sethandler、VSCode 用 vim.handleKeys 判归属
  • 内化分工哲学:vim 键位负责编辑,IDE 负责导航与理解代码 —— 融合,而不是对抗

1. 融合的哲学:一个编辑器,两颗大脑

第 11 章结尾说过:定位交给 IDE,加工交给 vim。本章把那句话落成配置文件。装好插件只是「能跑」;要跑得顺,得回答三个问题:哪些键听 vim 的、哪些听 IDE 的、出了冲突听谁的。默认状态下这个答案是凑合出来的 —— 比如 VSCodeVim 默认没开 easymotion、IdeaVim 的 Ctrl-a 与 IDEA 的多光标抢键 —— 本章的推荐配置就是把这三个问题一次性回答清楚。

先立总原则,后面所有配置都从它推导:vim 的价值在「编辑语言」(动词 + 名词、寄存器、宏),IDE 的价值在「语义理解」(索引、跳转、重构、调试)。所以编辑类按键一律让 vim 全权处理(方向键、Ctrl 键交给 vim 后不要手软);导航与语义类按键,能用 IDE 原生就别硬找 vim 等价物 —— Cmd+p 找文件、Cmd+Shift+f 全局搜索,这些键从来不与 vim 冲突,放手用。真正的灰色地带只有一小撮(本章 §8 的 Ctrl-a、Ctrl-f),那才是需要动手仲裁的地方。

还有一个心态问题值得先说破:不要试图把 IDE「调教回纯 Vim」。装插件的目的是在保留 IDE 全部能力的前提下,把编辑这一环换成 vim —— 侧边栏、鼠标、菜单、调试器一个都不用戒。看到本站演示里按 gb 时,鼠标点选区依然可用;按 Cmd+d 也好使。双轨并存的冗余不是浪费,是安全垫。

2. VSCodeVim:settings.json 推荐段

VSCodeVim 的配置住在 VSCode 的 settings.json 里(命令面板 → Preferences: Open User Settings (JSON))。下面这段是按官方 README 逐项核对的推荐值 —— 每一项都注明默认值,你可以按需删减:

{
  "vim.leader": "<space>",              // leader 键,默认是 "\"(反斜杠)
  "vim.easymotion": true,               // easymotion 标签跳,默认 false —— 建议开
  "vim.hlsearch": true,                 // 高亮全部匹配,默认 false —— 建议开
  "vim.incsearch": true,                // 边打边跳(默认就是 true,写出来求心安)
  "vim.useSystemClipboard": false,      // y/p 默认不与系统剪贴板互通(第 9 章讲过取舍)
  "vim.normalModeKeyBindingsNonRecursive": [
    { "before": ["<leader>", "d"], "after": ["d", "d"] },   // <leader>d = 删整行
    { "before": ["<leader>", "w"], "commands": [{ "command": "workbench.action.files.save" }] }
  ],
  "vim.handleKeys": { "<C-f>": false }   // 把 Ctrl-f 还给 VSCode 原生查找(见 §8)
}

几个核对结论划重点:①surround 不用配 —— vim.surround 默认已开,ys/cs/ds 开箱即用(§6);②相对行号不归插件管 —— VSCodeVim 没有行号设置,行号是 VSCode 编辑器自己的功能,想要第 3 章那种「当前行绝对、其余相对」,把 VSCode 设置 editor.lineNumbers 调成 relative 即可;③映射一律用 NonRecursive 版本的字段,防止映射引用自身时死循环;④leader 的官方默认是反斜杠 \,但社区主流推荐空格 —— 又大又独立,按不坏任何东西。

插入模式里的 Cmd 键(c/v/z/a)VSCodeVim 默认不拦截 —— 所以「插入模式里 Cmd-v 粘贴」天然可用,这是很多新手担心的问题,答案是不用管。真正被接管的是 Ctrl 系按键(Windows 上尤其明显),官方提供 vim.handleKeys 逐个归还,"<C-f>": false 就是把查找还给 VSCode 的标准写法 —— true/false 的意思是「这个键归不归 vim 管」。

3. IdeaVim:.ideavimrc 推荐全文

IDEA 这边更像真 Vim:配置是一个独立的 vimrc 文件,默认路径 ~/.ideavimrc(也支持 XDG 路径与 IDEA_VIM_CUSTOM_VIMRC 环境变量;想复用终端配置可以写一行 source ~/.vimrc)。改完文件后按 IDEA 弹出的 reload 提示(或重启)生效。推荐全文:

" —— 基础显示 ——
set number               " 绝对行号
set relativenumber       " 相对行号(与上一行同时开 = 当前行绝对、其余相对)
set incsearch            " 增量查找
set hlsearch             " 高亮全部匹配

" —— 插件 ——
set surround             " ys/cs/ds 三件套(VSCodeVim 默认开,这边要写一行)
set easymotion           " 标签瞬移

" —— 冲突仲裁(§8)——
sethandler <C-a> a:ide    " Ctrl-a 交还 IDEA:原生是「添加下一个匹配选中」

" —— leader 与映射 ——
let mapleader = " "
map <leader>f <Plug>(easymotion-s)      " 官方示例:前跳
map gh <Action>(ShowErrorDescription)   " 官方示例:gh = 悬停显示错误描述

IDEA 特色的一朵花是 <Action>():任何 IDE 动作都能绑到 vim 键上。动作 ID 哪里找?命令行敲 :actionlist 关键词 列出所有匹配的动作(比如 :actionlist Goto 找各种跳转),或在帮助菜单开「IdeaVim: track action IDs」后点菜单,状态栏就打印你点的动作 ID —— 把常用的动作绑上 leader,IDEA 的功能就长进了你的 vim 世界。注意官方提醒::action 命令适合命令行直接执行,要写进映射请用 <Action>(id) 形式。

4. 五根导航桥:gd / gh / K / Ctrl-o / Ctrl-i

编辑键归 vim,但「去看定义」「查文档」这类导航,vim 键可以直接扣动 IDE 的扳机 —— 这是两个插件最讨喜的缝合点。gd(go to definition)是官方文档明确支持的:VSCodeVim 里它等于转到定义,IDEA 里 IdeaVim 同样实现了它。往返闭环:

键作用等价的 IDE 原生什么时候用
gd跳到定义Cmd+b / Cmd+点击看函数/类型的实现,手指不离主键区
gh悬停提示(IDEA 可绑 <Action>(ShowErrorDescription))鼠标悬停看一眼类型签名/错误描述,不想动鼠标
K(shift+k)文档Quick Documentation查参数含义与返回值,比 gd 轻
Ctrl+o / Ctrl+i跳转链后退 / 前进Cmd+- / Cmd+shift+-看完定义原路返回(第 3 章 § 跳转表)
gb(下节)加多光标Cmd+d / Alt+J散落相同词逐个点名

工作流串起来就是一条流水线:gd 进定义 → 看完 Ctrl+o 回来 → 改两笔 → gd 再进下一个。跳转链是全局的(第 3 章讲过),gd 的每次跳跃都自动入链 —— 所以「去—回—再去」不需要你记路,链都替你记着。

三个键的分工别混:gd 是「去看实现」,K 是「查文档」,gh 是「扫一眼提示」—— 想知道这个函数怎么用按 K,想知道这个报错什么意思按 gh,想改它的实现才按 gd。轻重有序,导航的成本就低。还有一条纪律值得立:跳转链别当书签用 —— 链是「最近走过的路」,会被新的跳转不断冲刷;真正要反复回访的位置,用第 3 章的书签(ma / 'a)钉住,两套体系各司其职。

5. leader:自定义命令的发射台

vim 自带的键再全,也总有你想加的私货:一键保存、一键切换注释、一键跑测试。这些命令挂在哪?挂在 leader 键上 —— 一个专门留给自定义映射的前缀键,默认反斜杠,社区惯例改成空格(VSCode 写 "vim.leader": "<space>",IDEA 写 let mapleader = " ")。选空格的理由很实在:它是键盘上最大的键、普通模式下按空格本身只是右移一格(几乎没人用)、而且拇指按空格零位移 —— 白送的黄金地段。

使用 leader 的心智模型与第 5 章的「动词 + 名词」一脉相承:leader 是自定义动词的「待决状态」 —— 按下后 vim 挂起,等你补完后半段。久了会形成自己的方言:比如 <leader>d 删行、<leader>w 保存、<leader>f(IDEA)触发 easymotion、<leader>/ 关高亮…… 方言不用多,五六个高频命令就够回本。两个注意:①映射写进 normalModeKeyBindingsNonRecursive(NonRecursive 防自引用);②IDEA 里绑 IDE 动作用 <Action>(id) 而不是 :action(§3 的官方提醒)。

6. surround:加壳、换壳、拆壳

vim-surround 是 Vim 世界最著名的插件之一,两个 IDE 插件都内置了(VSCodeVim 默认开;IDEA 要写 set surround)。它解决的问题:给已经存在的文本穿衣服 —— 第 4 章的 ci" 是「改衣服里的内容」,surround 是直接改「衣服本身」:

按键口诀干什么典型场景
ys{对象}{壳}you surround给对象加壳(ysiw" 给词加引号)裸标识符变字符串、给词加括号强调
cs{旧壳}{新壳}change surround换壳(cs"' 双引号换单引号)引号风格统一、单行注释换块注释
ds{壳}delete surround拆壳(ds" 去掉引号)去掉多余的括号/引号包裹

壳的种类除了引号括号,还有标签:ysiwt<em> 把词包进 <em> 标签、cst<strong> 换标签(与第 4 章 cit 改标签内容正好互补:cit 改肉,cst 换皮)。可视模式里还有简写:选中后 S{壳} 直接包裹 —— 选中三行按 S) 就是给它们套括号。三件套的按键结构值得背熟:ys 是「加」、cs 是「换」、ds 是「拆」,后面接的都是「对象 + 壳」或「旧壳 + 新壳」,语法与第 4 章的文本对象完全复用。

7. gb 多光标:vim 键选人,IDE 光标干活

第 7 章 §9 与多光标划过界:块选管「几何列」,多光标管「内容匹配」。VSCodeVim 给内容匹配这条线留了 vim 键位 —— gb,官方文档明确记载:等效于 Cmd-d,「在下一个与光标词相同的词上添加光标」。IDEA 侧对应原生 Alt+J(IdeaVim 不拦截它,直接用原生即可)。

多光标的正确打开方式是「选人 → 打字 → Esc 收工」:gb 点名(几处点几个)、编辑键施工(ciw、A、x 都行,每根光标各执行一遍)、Esc 把光标收拢成一根。它与 * + n + .(第 8 章)是同任务的两种口味:dot 流水线逐处过目、顺带看语境;gb 多光标一屏选完、一次改完,但选人时就要看准。经验法则:出现点密集且确定无害(同一个文件里刚写错的变量名)用 gb;稀疏或语境可疑(可能与注释撞名)用 * + n + . 或 :s//gc。

把「同款修改发到多处」的三条路并排看一遍,选型就彻底清晰了:块选(第 7 章)按几何列圈,位置规则(每行同一列)时无敌;多光标按内容圈,散落但同词时顺手;宏(第 10 章)按「重复的动作序列」圈,每处要多步加工时称王。三条路的圈法分别是位置、内容、动作 —— 想清楚你要重复的东西属于哪一种,工具自动浮现。第 13 章的案例集会让这个选型器跑起来。

8. 冲突仲裁:一个键,两个主人

插件装上后,总有一小撮键「vim 想要、IDE 也想要」:Ctrl-a 在 vim 里是数字加一,在 IDEA 里(Windows/Linux 键位)是全选 Select All;Ctrl-f 在 vim 里是下翻页,在 VSCode 里是查找。这类冲突两边都给了一行式仲裁:

侧配置示例语义
IDEAsethandler 键 模式:归属sethandler <C-a> a:ide所有模式下 Ctrl-a 归 IDE;删掉这行(或写 a:vim)则归 vim
VSCode"vim.handleKeys": { "键": false }"<C-f>": falsefalse = 这个键不归 vim,交还 VSCode 原生

判给谁的原则还是 §1 那句话,但更具体:谁的功能在你的工作流里更常用就判给谁。天天写码要全选的场景,把 Ctrl-a 判给 IDE(数字加一还能用可视块或宏绕);第 10 章宏的重度用户、天天 Ctrl-a 造序列,就把它留给 vim(全选还有 Cmd-a)。Ctrl-f 判给 VSCode 查找也划算 —— 翻页有 Ctrl-d/Ctrl-u(vim 键,两边都保留)。仲裁没有标准答案,只有「你的工作流」这一个参考系。判完写进配置文件,别依赖记忆 —— 下次更新插件,GUI 弹窗的选择可能会被重置,配置文件里那行才是契约。

顺手列一份常见冲突清单(Windows/Linux 键位为主;mac 上 IDE 多用 Cmd 系,冲突天然少一档):Ctrl-d —— vim 翻半页,IDEA 复制当前行;Ctrl-y —— vim 上滚一行,IDEA 删除当前行;Ctrl-f —— vim 下翻页,VSCode/IDEA 查找;Ctrl-a —— vim 数字加一,IDEA 全选;Ctrl-r —— vim 重做,IDEA 里常被重构等动作占用。逐个想一遍「这个键我更常用它的哪一面」,然后一次性写进 sethandler / handleKeys —— 半小时的仲裁换来之后每天零弹窗,是配置阶段回报率最高的一笔投资。

9. easymotion:屏幕内没有「远处」

第 2、3 章的移动键管「按结构走」(词、行、段落),但「我要去屏幕中间那个 y」这种纯视觉目标,结构移动要接好几跳。easymotion 插件把这件事变成两键:按 <leader>f(IDEA 官方示例映射)进入标签模式,输入目标首字母,屏幕上所有候选位置亮起字母标签,按标签直达。VSCodeVim 设 "vim.easymotion": true 后用 <leader><leader> 前缀 + 目标字母,或按 §2 的映射改到 <leader>f:

它的适用边界也要认清:easymotion 管屏幕内的瞬移(候选都标在可视区域),跨屏长距离还是 /搜索 或 N%(第 3、8 章)更快。日常组合拳:近处 easymotion、结构处文本对象/移动键、远处搜索、跨文件 gd/:b —— 四档射程各司其职,你的手就再也不需要去够鼠标或方向键了。

配置齐了、特色键到位了 —— 下一章是毕业考:12 个真实重构案例,把全书功夫串成组合拳。

练习

练习 1:配置落地(10 分钟)

在你的主力 IDE 里完成:①抄入本章推荐配置(VSCode 改 settings.json / IDEA 建 ~/.ideavimrc);②逐项验证:按空格看状态是否挂起(leader 生效)、ysiw" 加引号(surround 生效)、<leader>f(或 <leader><leader>)看标签(easymotion 生效);③故意留一个冲突键不改,体会两个主人抢键的感觉,再用 sethandler/handleKeys 仲裁掉。通过线:每一项都能演示给别人看。

练习 2:导航桥往返(10 分钟)

任选项目:①光标放 10 个标识符上,各做 gd → 看两眼 → Ctrl+o 回;②练三次「深潜」:gd 进定义、再 gd 进更深的定义,然后 Ctrl+o Ctrl+o 两跳回起点,Ctrl+i 再进去;③对照原生:同样任务用 Cmd+b / Cmd+- 走一遍,确认两条通道背后是同一份跳转历史。通过线:往返全程不看键盘、不用鼠标。

练习 3:surround 与 gb 三连(10 分钟)

①surround:ysiw" 给词加双引号 → cs"' 换单引号 → ds' 拆掉,10 组;进阶:可视选中三行按 S) 套括号;②gb:造三行含同一变量,gb gb 加两根光标,ciw 一次全改,Esc 收工,5 组;③同任务换 * + n + . 再做一遍,体会两种节奏的差异。通过线:surround 三件套不用回想口诀。

练习 4:盲测毕业考(10 分钟)

常见陷阱

🕳 凭记忆写配置项,拼错或写了不存在的设置 VSCode 对不存在的设置会画波浪线但不会拦你保存,IdeaVim 对拼错的 set 只是默默忽略 —— 配置「看起来写了」实际没生效,排查起来最磨人。本章配置已对照官方文档核对(日期见 §10);自己加新项时,先在官方 README/文档里确认设置名与取值,再抄进文件。验证习惯:改一项 → 立刻按一下对应键确认生效,再改下一项。
🕳 改了 .ideavimrc 不重载,以为配置没写对 .ideavimrc 是启动时读的文件 —— 改完不生效先别怀疑人生:看 IDEA 通知栏有没有 reload 链接,点了重载(或重启 IDE)再试。VSCode 的 settings.json 则是即改即生效。另一个方向的新手坑:在 IDEA 里找「Vim 设置面板」 —— 核心配置都在文件里,GUI 面板只管冲突键等少数项。
🕳 冲突键仲裁只点弹窗,不写进配置 IdeaVim 弹出「这个键给谁」的弹窗时,选了 IDE —— 但插件更新或重置后弹窗会再弹,你的选择可能被冲掉。弹窗只解决当下,配置文件才是一劳永逸:判完立刻把对应的 sethandler 行(或删掉的行)写进 .ideavimrc。VSCode 同理 —— vim.handleKeys 写死,别依赖每次弹的选项。
🕳 多光标选过头,改完才发现选错一处 gb 连按时手指比眼睛快,第四处其实是注释里的同名 —— 改完才发现,还得逐处撤销。两个保险:①选人时逐个确认,别无脑连按;②选完先看一眼所有光标的位置再动手(IDE 会高亮全部光标);③真选错了 Esc 退出重来,成本只有几秒 —— 多光标是「租」来的,随时可以整单退掉。

VSCode / IDEA 差异(本章配置核对记录)

VSCode(VSCodeVim)— 核对来源:官方 README

  • 已核对项:vim.leader(String,默认 "\\")、vim.easymotion(默认 false)、vim.surround(默认 true)、vim.useSystemClipboard(默认 false)、vim.hlsearch(默认 false)、vim.incsearch(默认 true)、vim.handleKeys(示例 "<C-f>": false)、normalModeKeyBindingsNonRecursive 的 <leader> 写法
  • README 明确记载的特色键:gd(jump to definition)、gb(等效 Cmd-d 的加光标)
  • 明确不存在:行号类 vim 设置 —— 相对行号用 VSCode 原生 editor.lineNumbers: relative
  • Windows 注意:Ctrl 系按键默认被接管,按需用 vim.handleKeys 逐个归还;mac 上 Cmd 系(Cmd-c/v/z)插件不拦截,插入模式照常用

IntelliJ IDEA(IdeaVim)— 核对来源:官方 README + sethandler wiki

  • 已核对项:set surround、set easymotion(含官方映射示例 map <leader>f <Plug>(easymotion-s))、set nu/set relativenumber;配置路径 ~/.ideavimrc(另有 XDG 路径与 IDEA_VIM_CUSTOM_VIMRC 变量,可 source ~/.vimrc 复用)
  • 已核对命令:sethandler <快捷键> <模式>:ide|vim(官方 wiki,如 sethandler <C-a> a:ide);:action {id} 执行 IDE 动作,映射用 <Action>(id)(官方示例 map gh <Action>(ShowErrorDescription)),动作 ID 用 :actionlist 查
  • 注意:<Action> 映射不要配 noremap(官方提醒);多光标原生键是 Alt+J,IdeaVim 未拦截,直接用
  • 官方文档链接见本章附录说明:VSCodeVim README(github.com/VSCodeVim/Vim)、IdeaVim README(github.com/JetBrains/ideavim)及其 wiki「sethandler」页
